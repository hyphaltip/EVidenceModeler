# Release 2.5.0 (Rust)
- bugfix: augustus_GTF_to_EVM_GFF3.pl, augustus_merge_stop_codons_to_GFF3.pl,
  and the Rust augustus_to_evm_gff3 port all corrupted Augustus gene models
  run with --stopCodonExcludedFromCDS=False (funannotate's BUSCO training
  default): the stop_codon feature already lies inside the emitted CDS span
  in that mode, but the converters unconditionally re-added it as a second,
  overlapping CDS/exon segment, producing a negative-length intron that made
  downstream Augustus etraining reject the model. A stop_codon segment is
  now only folded in when it does not already overlap an existing CDS
  segment for that model; when it's a true adjacent segment (the historic
  --stopCodonExcludedFromCDS=True case) it is still merged into one
  continuous CDS span, matching Gene_obj::join_adjacent_exons(). The Rust
  port additionally used to silently drop stop_codon segments outright
  (never merging the adjacent case), truncating the CDS by 3bp; it now
  mirrors the corrected Perl logic exactly. Verified against a real
  funannotate BUSCO training run where 177/178 training models were
  corrupted by this bug.
- Packaging, CI, and docs hardening for the Rust rewrite (funannotate
  integration guide, module-file install instructions).
- Resolved all clippy warnings for CI compliance.
- Ported augustus_to_evm_gff3 and gff3_gene_prediction_file_validator from
  EVidenceModeler_rust.
- 99.6% gene-level parity with the Perl implementation.
- performance: convert_EVM_outputs_to_GFF3 and recombine_EVM_partial_outputs
  now write through a BufWriter. Before, each writeln! was its own write
  syscall (about 7 bytes per write in a measured run on a 241,057-contig
  genome), which is slow on GPFS. Output content is unchanged.
- convert_EVM_outputs_to_GFF3 logs progress (files done, files per second,
  estimated seconds remaining) every 5000 contigs.
- convert_EVM_outputs_to_GFF3 --skip_empty (off by default): a zero-byte
  evm.out writes no evm.out.gff3, and a stale .gff3 from an earlier run is
  removed. A missing evm.out is still an error. Note that an empty evm.out
  can also mean the EVM run failed, because funannotate redirects stdout to
  that file before it starts EVM.
- convert_EVM_outputs_to_GFF3 and recombine_evm_outputs now process contigs in
  parallel (rayon). New --threads N (default: RAYON_NUM_THREADS, else the CPUs
  available). Work follows the partitions-listing order instead of hash order,
  and each contig writes only its own files, so the per-contig output is the
  same as a serial run (tested across the 4096-entry batch boundary).
- convert_EVM_outputs_to_GFF3 --concat_out FILE writes every converted GFF3 to
  one file in listing order, so a caller need not walk the tree and copy each
  evm.out.gff3. The order can differ from a filesystem-order walk; the content
  is the same.
- bugfix: results no longer depend on hash iteration order. Evidence chains and
  prediction models entered the exon pool in std HashMap order, and the trellis
  keeps the first of equal-score ties. The intergenic score was a floating-point
  sum over ab-initio types in hash order, so its low bits changed from run to
  run. Both now use a fixed order (key order; type-name order). The golden Perl
  fixtures are unchanged.
- evidence_modeler writes evm.out through a buffer. funannotate redirects stdout
  to evm.out, and Rust stdout flushes on every newline, so each line was a
  separate write. evm-cli writes its pep, cds, bed and merged GFF3 files through
  a buffer too.

# Release 2.1.0 (Rust rewrite)
- Full Rust port of the EVM pipeline: evidence_modeler, partition_evm_inputs,
  recombine_evm_outputs, convert_EVM_outputs_to_GFF3, gff3_file_to_proteins,
  and the EVidenceModeler orchestrator.
- Drop-in replacement for Perl evidence_modeler.pl in funannotate.
- 99.4% gene-level parity and 97.0% protein sequence parity with the Perl
  implementation on a real fungal genome (Rhodotorula sphaerocarpa, 24
  scaffolds, ~20 Mb).
- Parallel execution via rayon (no external ParaFly dependency for the Rust
  path).
- CI: cargo fmt --check, cargo clippy -D warnings, cargo test, and golden
  integration tests on every PR.
